### Build (da sorgente, CUDA)

Toolchain rilevata sul sistema (nessuna installazione nuova):
- `nvcc`: CUDA compilation tools release 13.3, V13.3.33
- `cl`: MSVC 14.51.36231 (`C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools\VC\Tools\MSVC\14.51.36231\bin\Hostx64\x64\cl.exe`; NON nel PATH: cmake VS-generator lo risolve da solo)

Comandi esatti:

```
cd runtime/upstream/llama.cpp
cmake -S . -B build -G "Visual Studio 18 2026" -A x64 -DGGML_CUDA=ON \
      -DLLAMA_BUILD_TESTS=OFF -DLLAMA_BUILD_EXAMPLES=OFF \
      -DLLAMA_BUILD_SERVER=ON -DLLAMA_BUILD_TOOLS=ON -DCMAKE_CUDA_ARCHITECTURES=89
cmake --build build --config Release -j 12 --target llama-cli llama-server
```

Output: `build/bin/Release/llama-cli.exe`, `llama-server.exe`, `ggml-cuda.dll` (+ ggml.dll, llama.dll, mtmd.dll, common.dll).
Kernels CUDA: arch `compute_89/sm_89` only (Ada, target 4060 Ti). FA quant combos attive: `q4_0-q4_0, q8_0-q8_0, f16-f16, bf16-bf16`.
Warning noti (non bloccanti): LNK4098 LIBCMT; MSB8027 (`src/llama.cpp` vs `src/models/llama.cpp` stesso nome output — pattern unity build upstream); C4244 in header STL durante unity build. NCCL/OpenSSL mancanti non usati (single-GPU, HTTPS server disattivo: serve solo in LAN; documentato per M2 packaging).

## 3. Protocollo contesti popolati

La metodologia precedente usava `llama-cli` e filler in byte/char senza conteggio
del tokenizer: quei log non provano contesti popolati, prefill/decode o supporto
di una dimensione. Il protocollo aggiornato, inclusi guard, repliche, logging e
limiti sperimentali, è in [`gemma4-context.md`](gemma4-context.md). Harness:
`runtime/bench/bench_context.py`; output in `artifacts/bench/`.
